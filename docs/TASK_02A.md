# TASK 02A — распознавание русской речи

## Что реализовано

Серверный адаптер Deepgram Prerecorded (`nova-2`, `language=ru`, `diarize=true`, `utterances=true`, пунктуация и smart formatting). Выбрана модель Nova-2 с поддержкой русского языка; автоматической смены модели нет. Реальная точность русского языка, таймкодов и разделения спикеров должна быть проверена на согласованном коротком фрагменте. Неизвестный спикер помечается как Unknown speaker, а не выдумывается.

Реплики преобразуются в формат существующего редактора: start/end в секундах с миллисекундной точностью представления, исходный русский текст, идентификатор спикера, пустой перевод, голос для будущей озвучки и Draft. Точность самих таймкодов зависит от Deepgram. Модель не подтверждает личность или пол говорящего. Перевод и TTS не вызываются. Для настоящей транскрипции кнопка SRT выгружает русский текст.

Существующие CSS, расположение основных панелей и система авторизации сохранены. В панели исходного файла добавлены только необходимые действия распознавания, согласие на передачу данных/расходы и текстовый статус.

## Передача файлов и сохранение

1. Браузер читает длительность файла и запрашивает ID задания и краткоживущую подписанную ссылку.
2. Медиа загружается напрямую в приватный R2, минуя тело Vercel Function. PUT ограничен подписанным размером и типом, использует If-None-Match для запрета перезаписи.
3. Сервер проверяет наличие объекта, его размер и Content-Type. Длительность до вызова провайдера пока определяется браузером; это не заменяет серверный ffprobe и проверку реального MIME. Пилот предназначен для доверенного владельца, не публичной загрузки.
4. Перед вызовом Deepgram сервер атомарно создаёт постоянный claim в R2. Повторный start того же задания не делает новый платный запрос.
5. Vercel возвращает 202, затем `after()` выполняет короткий запрос распознавания и сохраняет результат в R2. Браузер опрашивает статус, а не повторяет распознавание. Процент показывается только во время реальной загрузки; Deepgram не сообщает процент распознавания, поэтому используется честный статус этапа.
6. ID хранится в браузере до сетевых действий. После обновления страницы результат берётся из R2; первоначальный результат хранится на сервере. Правки редактора автоматически сохраняются в localStorage этого браузера. Они пока не синхронизируются между устройствами. В том же браузере нельзя автоматически повторно применить исходный результат поверх уже внесённых правок.

Файлы и результаты приватны и остаются в существующем bucket, пока владелец их не удалит или не настроит lifecycle. Объекты имеют префикс `longray/asr/`. Удаление ссылки на задание в браузере не удаляет данные и не отменяет вызов провайдера. Не включайте публичный доступ к bucket. Не записывайте интервью или ключи в логи.

## Границы первого теста

До 120 секунд и 25 MB, MP3/WAV/M4A/MP4 с доступной браузеру длительностью. Пилот использует Vercel `after()` с `maxDuration=300`, таймаут запроса Deepgram — 240 секунд. Доступная длительность функции зависит от настроек и возможностей текущего проекта Vercel; не переходите на платный план автоматически.

Это не полноценная очередь и не worker для часовых интервью. После закрытия вкладки сервер продолжает короткую обработку, но перезапуск/таймаут функции может её оборвать. Зависшее задание отображается как uncertain после 6 минут; повторного платного вызова нет. Проверяйте историю запросов Deepgram, прежде чем сознательно создавать другое задание. Автоматические платные retries отключены.

Договор типов предусматривает исходную длительность до 65 минут, а прямое хранилище и отдельные стадии уже отделены от UI. Однако пилотный endpoint такие файлы **не запускает**. Для 65 минут нужны отдельный worker, ffprobe, multipart/resumable upload, контроль расходов, leases/checkpoints и тестирование больших файлов. Они не представлены как готовые возможности TASK 02A.

## Настройка только через браузер

Новый проект Vercel не нужен. В существующем проекте откройте **Settings → Environment Variables** и добавьте для нужных окружений Production/Preview:

- `DEEPGRAM_API_KEY` — серверный ключ Deepgram с минимально необходимыми правами.
- `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME` — доступ только к уже согласованному приватному bucket.
- `DEEPGRAM_PILOT_ENABLED=false` — оставьте выключенным до отдельного согласия на первый платный запрос.

Не меняйте `STUDIO_ACCESS_PASSWORD`. Не используйте префикс NEXT_PUBLIC_ для ключей и не передавайте значения в чат. В этой задаче ключи не добавляются в Codex Cloud и облачные ресурсы не создаются. Если R2 ещё нет, сначала отдельно согласуйте подключение и условия оплаты, даже если предполагается бесплатная квота.

В настройках CORS существующего R2 bucket разрешите точный адрес вашего приложения (и только нужные подтверждённые Preview-адреса):

```json
[
  {
    "AllowedOrigins": ["https://YOUR-EXISTING-PROJECT.vercel.app"],
    "AllowedMethods": ["PUT", "GET", "HEAD"],
    "AllowedHeaders": ["Content-Type", "If-None-Match"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 600
  }
]
```

Замените шаблон на реальный адрес. CORS не делает bucket публичным. Content-Length браузер устанавливает сам; его размер включён в подпись. Доступ R2 нужен для чтения, записи, HEAD и условного PUT. Проверьте поддержку условных запросов на своём bucket до реального платного запуска.

После изменения переменных выберите **Deployments → Redeploy**. Для начала реального теста сначала получите отдельное разрешение владельца на один фрагмент и бюджет. Затем установите `DEEPGRAM_PILOT_ENABLED=true` и снова сделайте Redeploy. Это лишь открывает кнопку — платный вызов всё равно требует галочки и нажатия пользователем.

## Как проверить через браузер

1. Откройте существующий HTTPS-адрес Vercel и войдите как обычно.
2. Выберите русский аудиофрагмент 1–2 минуты, лучше MP3 или WAV. Сам выбор файла не запускает API и не отправляет его в R2.
3. После отдельного разрешения на расходы поставьте галочку согласия и нажмите **Recognize Russian speech**.
4. Дождитесь загрузки и статуса распознавания. Можно обновить страницу: должен восстановиться тот же ID задания, без повторного запроса Deepgram.
5. Проверьте полноту русского текста, таймкоды начала/окончания и смены спикеров по оригиналу. Вьетнамский перевод должен быть пустым. Скачайте русский SRT.
6. При ошибке не нажимайте повторно вслепую: проверьте сообщение и Deepgram Usage/историю запросов. Сохраните ID задания, но не отправляйте приватный текст в логи.

Реальное качество не считается подтверждённым до этого теста. Часовой сценарий не считается проверенным коротким пилотом.

## Ориентировочная стоимость

Стоимость распознавания 60 минут: `60 × (тариф ASR за минуту + доплата diarization за минуту)`. Для предварительного бюджета разумно резервировать примерно **$0.40–$1.00 за час**, только за Deepgram; это не подтверждённый актуальный тариф. Ставка зависит от модели и аккаунта. Точный текущий тариф следует проверить в https://deepgram.com/pricing и кабинете перед согласованием. Для 1–2 минут ориентир составляет несколько центов; предлагаемый потолок первого согласования — $0.05. Инфраструктура и операции хранения считаются отдельно. Бесплатные кредиты не гарантируются.

Официальные страницы Deepgram в среде разработки заблокированы сетевой политикой (403), поэтому актуальные цены и текущий каталог моделей онлайн здесь не подтверждены. Реальные API-запросы не выполнялись.

## Проверки разработчика

- `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`.
- `E2E_SERVER_COMMAND='npm start' PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e`.
- Mock-ответы проверяют русские символы, паузы, спикеров, fallback по словам, ошибки провайдера, конкурентный старт, отсутствие повторных платных запросов и восстановление.
- Browser E2E перехватывает только сетевые ответы теста; production не имеет mock-режима, подменяющего настоящий результат. Скриншоты и визуальные Preview не создаются.

Прямая ссылка на обновлённый Vercel deployment указывается только после получения настоящего адреса и подтверждения развёртывания; адрес не выводится из названия репозитория. Push в подключённую ветку может инициировать автодеплой, но сам по себе не доказывает успешный статус Ready.

## Проверка после добавления ключа в Vercel

Если `DEEPGRAM_API_KEY` и `STUDIO_ACCESS_PASSWORD` уже заданы, вводить их повторно или передавать разработчику не нужно. Обновите существующий deployment через **Deployments → Redeploy**: изменения переменных не применяются к ранее собранной версии автоматически.

Панель распознавания показывает точные названия отсутствующих переменных. Защищённый endpoint `/api/asr/config` проверяет только наличие настроек на сервере, не обращается к Deepgram и не раскрывает значения. Отсутствие ключа в среде Codex ничего не говорит о его наличии в Vercel. Проверка наличия переменной также не подтверждает валидность ключа или права доступа к bucket: это проверяется отдельно, без самовольного платного распознавания.

Если после Redeploy отсутствуют только `R2_*`, API-ключ Deepgram не требуется менять: необходимо настроить уже согласованное приватное хранилище и CORS по инструкции выше. `DEEPGRAM_PILOT_ENABLED` оставьте выключенным до отдельного согласия на расходы. Новый проект Vercel для этого не создавайте.
